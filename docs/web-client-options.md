# Web client options

Research snapshot: **2026-11-07, 05:01–05:04 UTC**. Source review only; no upstream code copied or deployments tested.

**Evaluate Cloud Mail first for a complete mailbox application. For Fumi's own frontend, prefer independent UI/editor components behind a small API adapter.** Mailflare remains a useful React reference, but adopting its whole workspace is unnecessary for a mailbox-only goal. Zero's UI is substantially coupled to its backend. Agentic Inbox has a clearer frontend/API seam, but no recent upstream default-branch development was observed.

### Where an adapter is required

- **Cloud Mail:** its [mailbox page](https://github.com/maillab/cloud-mail/blob/d115f4ccc5cb5fb9c602b3ba364acbca6d19f274/mail-vue/src/views/email/index.vue#L18-L37) imports account/email/settings stores. [Request functions](https://github.com/maillab/cloud-mail/blob/d115f4ccc5cb5fb9c602b3ba364acbca6d19f274/mail-vue/src/request/email.js) call concrete `/email/*` endpoints; [Axios](https://github.com/maillab/cloud-mail/blob/d115f4ccc5cb5fb9c602b3ba364acbca6d19f274/mail-vue/src/axios/index.js#L1-L37) expects a local token and `{code,data,message}` envelope. The [mail-list component](https://github.com/maillab/cloud-mail/blob/d115f4ccc5cb5fb9c602b3ba364acbca6d19f274/mail-vue/src/components/email-scroll/index.vue) accepts callbacks but also imports app stores. This supports a feasible adapter seam, not a claim of drop-in reuse.
- **Mailflare:** [MessageFolderPage](https://github.com/hieunc229/mailflare/blob/d4dc8337c3f0f833f8eb7dfa9d8daa00d39ad310/src/components/messages/message-folder-page.tsx#L3-L30) uses Next links, mailbox/search contexts, message hooks and API types. [Mailbox options](https://github.com/hieunc229/mailflare/blob/d4dc8337c3f0f833f8eb7dfa9d8daa00d39ad310/src/components/mailbox-provider-utils.ts#L34-L44) come from `/api/mailboxes` through its session wrapper. Removing unrelated navigation does not detach those contracts.
- **Zero:** its [query provider](https://github.com/Mail-0/Zero/blob/36132735ca3b734b23f48127f9271c80d1ba76e7/apps/mail/providers/query-provider.tsx#L1-L20) imports the server `AppRouter`, auth and IndexedDB persistence. [Thread hooks](https://github.com/Mail-0/Zero/blob/36132735ca3b734b23f48127f9271c80d1ba76e7/apps/mail/hooks/use-threads.ts) call typed server APIs and depend on provider types, session and notification/cache semantics. [Mail-list source](https://github.com/Mail-0/Zero/blob/36132735ca3b734b23f48127f9271c80d1ba76e7/apps/mail/components/mail/mail-list.tsx) also imports server summaries and application state. Selected files need license review: [MCP headers](https://github.com/Mail-0/Zero/blob/36132735ca3b734b23f48127f9271c80d1ba76e7/apps/server/src/routes/agent/mcp.ts#L1-L16) conflict with the root's simple MIT description.
- **Agentic Inbox:** [API service](https://github.com/cloudflare/agentic-inbox/blob/48039bb6785af34e592c2966f87cde2b255c4c80/app/services/api.ts) plus [query hooks](https://github.com/cloudflare/agentic-inbox/blob/48039bb6785af34e592c2966f87cde2b255c4c80/app/queries/emails.ts#L5-L47) offer a clearer boundary. Its [README](https://github.com/cloudflare/agentic-inbox/blob/48039bb6785af34e592c2966f87cde2b255c4c80/README.md) explicitly says every admitted Access user/MCP client can access all mailboxes; Durable Object separation is not mailbox authorization.

### Component-only alternatives

[React Email Editor documentation](https://react.email/docs/editor/overview) describes a host-embeddable TipTap/ProseMirror editor. Its [README](https://github.com/resend/react-email/blob/674d8ec2804b86be5d99156383fb1810179847bf/README.md) supports sending generated HTML through any provider; adopting the editor does not require Resend delivery.

[shadcn/ui](https://github.com/shadcn-ui/ui) has **127,535 stars**, an [MIT license](https://github.com/shadcn-ui/ui/blob/42f3bb63b46a69e52a24bd005cdc9ec15ba7a7b9/LICENSE.md), [November 6 development](https://github.com/shadcn-ui/ui/commit/42f3bb63b46a69e52a24bd005cdc9ec15ba7a7b9) and an [October 27 release](https://github.com/shadcn-ui/ui/releases/tag/shadcn%404.23.0). It is suitable for generic controls. The inspected current tree has no mailbox example, and the historical `/examples/mail` URL returned 404; do not equate library maintenance with a maintained mailbox frontend.

[Mainly](https://github.com/arikchakma/maily.to) has **3,994 stars** and modular [React editor usage](https://github.com/arikchakma/maily.to/blob/042d13169b39e0ae8c692a25693bebdbb9b894c0/packages/core/readme.md), but default-branch development ends [July 21](https://github.com/arikchakma/maily.to/commit/042d13169b39e0ae8c692a25693bebdbb9b894c0) despite a November `pushed_at`. It is a secondary editor choice when recent maintenance is a hard preference. EmailBuilder.js similarly has no recent inspected default-branch development. Roundcube is active and popular, but its [PHP/IMAP architecture](https://github.com/roundcube/roundcubemail/blob/3a1d740f029684255ea67dc235c321c95c3f2e62/README.md) makes it a substantial port rather than a frontend for a Workers/D1 API.

## Next decision

Compare **Cloud Mail as a complete application** with **a small Fumi frontend using independent components**. If React is required, prototype one synthetic list/reader/composer flow against Fumi's own message/thread/attachment contract before committing to a Mailflare or Zero fork. The coupling assessments above are engineering inferences from source, not measured porting estimates.
